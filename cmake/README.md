# CMake structure

`cpp_request` keeps the root `CMakeLists.txt` as an orchestrator. Project behavior is split by responsibility:

- `modules/` — project options, target policy, tests, benchmarks, examples, and install/export rules.
- `packages/` — development-only third-party discovery with `find_package()` first and `FetchContent` fallback.
- `tools/` — optional developer tooling such as clang-format, clang-tidy, and Doxygen.
- `templates/` — inputs for files generated into the build/install tree.

Normal CMake configure must not modify files in the source tree. In particular, `vcpkg.json` is source-controlled input and is not generated by CMake.

## Main options

- `CPP_REQUEST_BUILD_TESTS`
- `CPP_REQUEST_BUILD_BENCHMARKS`
- `CPP_REQUEST_BUILD_EXAMPLES`
- `CPP_REQUEST_ENABLE_INSTALL`
- `CPP_REQUEST_ENABLE_WARNINGS`
- `CPP_REQUEST_WARNINGS_AS_ERRORS`
- `CPP_REQUEST_ENABLE_SANITIZERS`
- `CPP_REQUEST_ENABLE_IPO`
- `CPP_REQUEST_ENABLE_NATIVE_OPTIMIZATION`
- `CPP_REQUEST_ENABLE_CLANG_TIDY`
- `CPP_REQUEST_ENABLE_CLANG_FORMAT`
- `CPP_REQUEST_ENABLE_DOXYGEN`

Tests, examples, and install rules default on only when `cpp_request` is the top-level project. Benchmarks and developer tools are opt-in. For compatibility with conventional CMake callers, an explicitly supplied `BUILD_TESTING` value is used as the default for `CPP_REQUEST_BUILD_TESTS`.
